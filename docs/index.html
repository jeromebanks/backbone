From contradictory clinical records to answers you can audit

A prototype that turns overlapping, conflicting behavioral-health documents into a persistent clinical abstraction, then answers questions with deterministic computation. Every number traces back to encounters, reconciliation decisions, verified source passages and original files.

The problem

Backbone reviews clinical records to decide what care a patient actually received, and whether the documentation supports it. The information is spread across clinical notes, attendance rosters, corrections, schedule exports, telehealth logs, billing extracts, imported summaries and a treatment plan. These documents often describe the same contact more than once, disagree on details, or correct one another later.

The exercise asks for five answers about one patient's four-week episode: sessions, minutes, weekly plan compliance, a reconstruction of two specific days, and the symptom course. It also asks for a design that reuses work across questions and scales to 500,000+ documents. A later document does not automatically override an earlier one.

How it works

Two pipelines share one persisted abstraction. The language model works only at the semantic edges: reading one document, choosing operations for a question, and phrasing the computed result. Everything in between is ordinary deterministic code.

1 · Evidence: claims, not facts

One LLM call per document records what that document asserts: intervals, dispositions, signatures, corrections, copies, assessments and plan goals. It never computes durations. Every quote is located in the source by code, which also assigns the line numbers. The result is cached by content hash, so re-runs are free.

2 · Reconciliation: versioned rules

Pure Python rules (R0–R9) group records into encounters, apply corrections, discard drafts and billing as attendance evidence, and compute minutes by interval arithmetic. Unresolved disagreement is kept as a range. Every choice is logged as a decision.

3 · Projection: one place for clinical math

Counts, therapy days, minutes, Monday–Sunday weeks, the plan in effect, and MET / NOT_MET / UNDETERMINED verdicts are all computed in a single module, so every query uses the same semantics.

4 · Questions: a typed query plan

The LLM turns a question into a validated QueryPlan over four operators. Code executes it in milliseconds. The LLM then writes the answer from the results alone, and a post-check verifies every number and citation.

Traps in the record, and how they're handled

A correction, then an older copy received later

The Jan 19 roster said Rowan left group at 11:30 (BH-D102). A signed correction changed it to 11:15 (BH-D103). On Jan 26 the uncorrected roster was resent (BH-D104).

The field-scoped correction wins, and the resend is treated as a copy. The old value would also overlap the 11:15 individual session, which the overlap rule detects.

A draft note and a charge for a no-show

An unsigned, template-generated note says "attended the full session", and a group charge was posted (BH-D112). The signed register says no-show (BH-D108).

Drafts and billing rows are not attendance evidence. The session is excluded, and the reason is logged.

Two signed notes disagree

For the Jan 26 individual session, one clinician records 09:00–09:50 (BH-D110) and the co-clinician 09:10–09:50, noting when Rowan entered (BH-D111).

Neither corrects the other, so the session is carried as 40–50 minutes. Week 4 is therefore UNDETERMINED, not guessed.

Stated durations that aren't patient time

The Jan 30 family note says "45 minutes", but the partner was seen alone for the first 15 (BH-D113). Group notes list 90-minute slots with a 15-minute break, and late arrivals and early departures appear only on rosters.

Minutes are computed from intervals: patient present, minus breaks, disconnections and partner-only portions. Stated totals are only cross-checks.

One session, two video calls

The Jan 21 telehealth session dropped and reconnected under the same appointment (BH-D106).

That is one encounter with two contact segments: 20 + 25 = 45 minutes. The 10-minute gap is excluded.

Copies that look like new measurements

An import receipt dated Jan 26 (BH-D014) repeats the Jan 16 PHQ-9 (form HG-Q116).

Assessments are identified by instrument, completion date and form, so it is one assessment, not two. Three distinct PHQ-9s: 18 → 14 → 10.

Contacts that aren't therapy

A partner-only collateral visit, a call between professionals, medication management, outreach calls.

These are classified and excluded with reasons. They never count toward therapy days or minutes.

Duplicate notes for one visit

Primary and co-facilitator notes for the Jan 9 family session (BH-D007, BH-D008), plus schedule exports that repeat every appointment.

Records are grouped by encounter identity. Many records make one session.

Reconciliation rules

RuleWhat it does
R0Reject any claim whose quote cannot be located in the source text (none rejected in this corpus).
R1Encounter identity by ID; otherwise same date + service type (+ overlapping times); otherwise a separate contact.
R2Drafts, templates and billing rows are not attendance evidence.
R3Explicit corrections replace only the field they correct; retransmitted copies carry no independent weight. Precedence follows relationships, never document date.
R4Evidence tiers (notes, registers, corrections, platform logs above schedule listings). Disagreement within the deciding tier is a dispute, carried as a range.
R5A session counts if it is psychotherapy, attended, and the patient was present. Unknown attendance is "uncertain", never zero.
R6Minutes = present intervals − breaks − disconnections − patient-absent portions.
R7A patient cannot be in two encounters at once; overlaps are flagged.
R8Assessments are identified by instrument, completion date and form; imports and copies are not new assessments.
R9Plan requirements apply by effective date. A revision supersedes earlier goals from its start date. A week spanning a change is judged on whole-week totals against each plan, and is UNDETERMINED if they disagree.

Uncertainty: ranges and three-valued verdicts

Every quantity is a range [low, high]. A goal is MET if it holds at both ends, NOT MET if it holds at neither, and UNDETERMINED otherwise. The system never picks a value to make a verdict look certain.

The query DSL

Questions compile to a typed, validated plan. The model never writes SQL or code. Each step shares one Scope (patients or "all", dates, service types, include excluded records, include evidence) and runs one of four operators:

OperatorReturns
careSessions, therapy days and minutes/hours (with ranges) by type, day, week or patient; optionally every record that doesn't count, and why.
compliancePer week: the goal in effect, delivered totals, the verdict, exclusions; runs of N weeks below goal (definite vs dependent on unresolved records).
timelineChronology of encounters, documents (and what each asserted), decisions, assessments and observations. A one-day scope reconstructs that day.
compareCare before vs after a date or a treatment-plan change.

As JSON (what the model emits)

{"question": "Weekly plan compliance, Jan 5–30",
 "steps": [
  {"op": "compliance",
   "scope": {"patients": ["HG-M042"],
             "start": "2026-01-05", "end": "2026-01-30"},
   "consecutive_below": 2}]}

As Python (same plan object)

from backbone.dsl import care
q = (care.for_patient("HG-M042")
         .during("2026-01-05", "2026-01-30")
         .compliance(consecutive_below=2))
q.explain(); q.execute(conn); q.to_sql(conn)

Every operator returns the same machine-readable envelope: totals, groups, facts, human-readable arithmetic, exclusions, conflicts, decisions, evidence passages (document, line, quote) and the exact parameterized SQL.

Performance & scale

All figures are measured on a laptop (). Scale figures use a synthetic collection: the real patient's reconciled records cloned per patient, which measures the query layer only.

Toward 500K–1M documents (estimates)

  • The first bottleneck is LLM extraction. At the measured ~$0.045 and ~13 s per document, 1M documents is ≈ $45K at list price and ~3 weeks at 8-way concurrency. Prompt caching, the Batch API (−50%) and a cheaper extractor validated against this corpus are the levers. The content-hash cache already makes re-deliveries free.
  • Next: collection-wide compliance. It is linear, at one query per patient-week. The fix is to persist a weekly projection per patient on reconcile and compute streaks in SQL.
  • Then the single SQLite writer. Reconciliation is already per patient (~4 ms) and partitions cleanly → Postgres plus a queue of patients whose records changed.

Limitations & next steps

  • Extraction is a single pass. Passing mentions of appointments sometimes become separate "unidentified contacts". They never count as therapy, but they add noise. Next: an agreement harness (k runs, cheaper models) measuring field-level stability, and stricter handling of mentions.
  • The post-check verifies numbers and citations, not prose interpretation.
  • There is no second planning round if the first query plan is insufficient.
  • Provider identities are not merged, deliberately: "N. Ellis" at the desk is not assumed to be "Nora Ellis, LCSW".
  • The API-key LLM backend is implemented but not exercised; all results used a Claude subscription via Claude Code.

Running it

python -m pytest -q                                   # 34 tests, no LLM calls
python -m backbone verify-answers                     # saved answers reproduce exactly
python -m backbone plan plans/weekly_compliance.json  # hand-written plan, no LLM
python -m backbone ingest path/to/new_doc.txt         # extracts only new docs; re-reconciles that patient
python -m backbone ask "Which weeks met the day goal but not the minute goal?"
python docs/build_site.py                             # regenerate this page from the data
